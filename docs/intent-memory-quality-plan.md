# Nagi 群聊参与、记忆与画像质量计划

2026-11-19 确认。面向 Nagi 的开发者和测试群评审者。先建立逐条入站的质量基线，再比较提示词与参与策略，最后用同一套评估验证跨群画像。下表记录评审当时的状态，下面四个阶段是待交付工作。

## 第一阶段 · 以一条入站为单位做 Langfuse 评估

1. 控制台从入站消息打开详情，用同一入站标识串起接收 trace、任务的每次执行、选用的规则或模型、话题选择、召回、回复生成、工具调用和逐条 QQ 回执。待处理、策略拦截、沉默、执行失败分别展示。决策、任务状态、QQ 投递结果独立记录，例如审计超时仍可同时有已确认的 QQ 回执。执行统计按入站去重，投递统计按投递记录计数。对禁止留存的作用域保留既有授权边界，单列可观测的拦截计数。
2. 首批标注这 35 条，再从获准会话补充普通群聊和多人交错的反例。每项冻结消息到达时可见的前文、引用、附件类型与可用状态、话题和策略版本。预期包含「应回／可回可不回／应沉默」、回复对象、可接受的话题和动作。消息、媒体与身份按项目权限脱敏，评审者可对有分歧的样本保留多种合理答案。
3. 按群或整段话题划分调优集与保留验收集，连续追问和重复发送进入同一侧。线上版和候选版在同一数据集版本、相同模型配置下回放，分别记录规则、Prompt 和代码版本。回放隔离 QQ 发送、画像和记忆写入。确定性的选择由程序评分，回复自然度由人工盲评，可判平局。将逐条分数和汇总写回 Langfuse。[数据集实验](https://langfuse.com/docs/evaluation/experiments/experiments-via-sdk) · [写入 Scores](https://langfuse.com/docs/evaluation/evaluation-methods/scores-via-sdk)

| 指标 | 计算与复核 |
| --- | --- |
| 漏回与打扰 | 应回召回率 = 判回复的应回数 / 人工应回数。误插话率 = 判回复的应沉默数 / 人工应沉默数。中间档单列。每组给出分子、分母，空分母标为无样本。 |
| 续接与回复 | 在有明确对象、话题的样本中计算命中率。人工比较有 QQ 回执的实际回复，离线使用模拟投递捕获的正文，检查是否接对内容、有无重复、多余追问或虚构附件。 |
| 抽取与召回 | 人工标应保存的事实、主体、适用范围、来源及可接受的记忆 ID。分别统计抽取精确率、召回率、检索 Recall@3（对每个有预期记忆的查询，用前三条命中的预期 ID 数除以该查询的预期 ID 总数，再对查询取平均）、串人和越域次数。 |
| 成本与送达 | 每百条入站的 SystemOne 与 Agent 模型调用数、输入输出 token、每百条入站确认的 QQ 投递数。延迟按入站到首次确认回执统计 P95，未确认与确认耗时分别报告。模型单价核验后再计算金额。 |

**验收**　同一份 Experiment 能逐条对照两版、按冷场／活跃、图文／纯文本等场景查看误判，并从线上样本追到原决策和实际回执。基线同时报告待标注数、样本覆盖和成本。第一批数据用来确定后续可接受的质量与成本变化范围。

## 第二阶段 · 版本化模型实际使用的提示词

- 纳入管理的内容包括回复人设和语气、SystemOne 决策问题、活跃话题选择、记忆抽取、同义检索改写。决策问题同时记录生效的问题顺序、阈值和对应动作，以便分别试验问题措辞与策略。
- 控制台的生效预览、回放和运行共用一处组装逻辑。按层展示账号角色、群聊或私聊补充、服务端说明、运行上下文的来源。将 Langfuse 模板名称和确切版本关联到相应模型调用，复合模板记录各层版本与最终渲染哈希。授权、预算、工具执行和失败停发由服务端强制执行。预览和 trace 沿用正文导出与脱敏设置。
- 在 Langfuse 比较候选，验证后将指定版本同步到 Nagi 本地发布。运行读取本地生效快照，远端暂不可用时仍可对话。回滚后记录重新生效的版本。[版本与发布标签](https://langfuse.com/docs/prompt-management/features/prompt-version-control) · [从模型调用关联 Prompt](https://langfuse.com/docs/prompt-management/features/link-to-traces)

**验收**　选一次测试群真实运行，在控制台定位每段提示词的来源，并用相同输入核对最终渲染哈希。在对应的模型观测上可查 Prompt 版本及该版本的实验分数。发布和回滚各验证一次。

## 第三阶段 · 对比群聊参与策略

- **冷场时**，明确 @Nagi、引用 Nagi 的消息、句首或句尾直接喊名（含小写）、直接喊它看图可唤醒 Agent。仅在指向不明且允许参与时使用 SystemOne。记录当前和引用消息的文本、指向与媒体类型。其他群友相互点名或第三人称提到 Nagi 都需要负例。
- **有活跃话题时**，通过作用域与预算检查后跳过 SystemOne。Agent 针对「机器人账号＋群＋话题」选择续接、开启、结束或沉默。一个群可以有多个并行话题，同一话题允许其他群友加入。优先依据回复引用、刚才邀请谁补发什么、当前附件和本话题的最近发言。
- **等待下一条时**，`wait` 持久化话题及五分钟空闲期限，释放当前执行。新入站可恢复等待，明确收尾或到期结束。无关闲聊不为旧话题续期。重启后按已保存的期限恢复，已确认发送的消息避免重发。
- **组装回复时**，先给当前消息、授权引用和选中话题的必要上下文。更早的聊天按需检索。仓库已有可选的 `history.search`，Elasticsearch 找候选 ID，PostgreSQL 按当前授权回读正文。先测检索命中和 token 消耗，再决定是否扩展索引。工具随可用输入提供，例如只有图片时使用看图能力，只有文本且没有可用视频引用或链接时省去视频检查工具。[历史检索实现](../internal/conversation/application/history_search.go)

| 固定回归片段 | 预期 |
| --- | --- |
| 冷场直接问「Nagi你看看这个是什么」并带图片 | 唤醒，按本条实际可用图片作答。读取失败准确告知。 |
| 「nagi?」得到回应，随后发「Nagi你看看这个是什么」并带图，或应 Nagi 邀请只补一张图 | 进入活跃话题，跳过 SystemOne，能接到补发图片。 |
| 「我饿了，今天吃什么啊 Nagi」与另一人纠正上个话题里的图片名称交错到达 | 接住句尾呼叫。饮食和图片分别续接到各自的话题。 |
| 无活跃话题时群友说「大家好」，或两个群友互发无关表情 | 对两位群友之间的消息保持沉默，详情可查判断结果和零投递。 |
| 单独发「你看看这个是什么」，当前、引用和已授权上下文均无媒体 | 若决定回复，简短询问指的是什么。不会虚构视频解析失败。 |
| 等待期间重启，或等待超时后再次点名 | 前者能恢复并处理一次。后者重新判断，保留原话题已结束的记录。 |

**验收**　在相同保留集对比线上版与候选版的应回召回率、误插话率、话题命中率、模型用量和 P95。单列带图和普通闲聊的得失。回归通过后按应用 PR、GitOps PR 的顺序发布到 dev-nagi，在测试群用集群真实模型核对 QQ 回执、沉默记录和 Langfuse trace。

## 第四阶段 · 在不同群认出同一个人

| 画像与身份键 | 可使用的信息 |
| --- | --- |
| 用户画像 · 机器人账号＋QQ 用户 ID | 本人确认且可跨群使用的称呼、长期偏好。改群名片后仍沿用相同身份。 |
| 群画像 · 机器人账号＋群 ID | 本群约定、共同活动、术语、群友接受的参与频率和表达风格。 |
| 群成员画像 · 机器人账号＋群 ID＋QQ 用户 ID | 此人在本群的名片、参与的话题与本群内成立的互动习惯。 |

复用目录身份、现有记忆候选与审批。每项事实保留来源消息、主体、适用范围、确认时间和更正状态。先判定当前场合可用的事实，再做相关性排序。A 群的一次约饭仅用于 A 群。本人明确说“以后都叫我小羊”才可作为跨群称呼候选。私聊内容遵循原会话的可见范围。

**验收**　用同人不同群、同名不同人、转述、群体事实、更正称呼和同义问法做配对测试。更正后的事实正常召回，原事实退出生效结果。固定反例中的串人、跨群私聊泄露均为 0。盲评实际回复是否在合适的话题才使用记忆，并记录画像命中对自然度与 token 的影响。
