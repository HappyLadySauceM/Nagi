# Nagi 群聊参与、记忆与画像质量计划

2026-11-19 确认。面向 Nagi 的开发者和测试群评审者。下表保留初次评审的历史观测。后续阶段记录 Cycle 2 的交付与验收口径，实际发布和签收以对应任务的记录为准。先签收 HAP-51 首阶段和 HAP-48 的直接点名完整送达。HAP-56 在呼叫身份 v2 上线后独立推进，HAP-52 在后续单独验证跨群画像。

## 第一阶段 · 以一条入站为单位做 Langfuse 评估

1. 控制台从入站消息打开详情，用同一入站标识串起接收 trace、任务的每次执行、选用的规则或模型、话题选择、召回、回复生成、工具调用和逐条 QQ 回执。待处理、策略拦截、沉默、执行失败分别展示。决策、任务状态、QQ 投递结果独立记录，例如审计超时仍可同时有已确认的 QQ 回执。执行统计按入站去重，投递统计按投递记录计数。对禁止留存的作用域保留既有授权边界，单列可观测的拦截计数。
2. 首批标注这 35 条，再从获准会话补充普通群聊和多人交错的反例。每项冻结消息到达时可见的前文、引用、附件类型与可用状态、话题和策略版本。预期包含「应回／可回可不回／应沉默」、回复对象、可接受的话题和动作。消息、媒体与身份按项目权限脱敏，评审者可对有分歧的样本保留多种合理答案。
3. 按群或整段话题划分调优集与保留验收集，连续追问和重复发送进入同一侧。线上版和候选版在同一数据集版本、相同模型配置下回放，分别记录规则、Prompt 和代码版本。严格对照使用冻结的策略和输入，执行仍须通过当前授权检查。回放隔离真实 QQ 发送、画像和记忆写入。确定性的选择由程序评分，回复自然度由人工盲评，可判平局。将逐条分数和汇总写回 Langfuse。[数据集实验](https://langfuse.com/docs/evaluation/experiments/experiments-via-sdk) · [写入 Scores](https://langfuse.com/docs/evaluation/evaluation-methods/scores-via-sdk)

| 指标 | 计算与复核 |
| --- | --- |
| 漏回与打扰 | 应回召回率 = 判回复的应回数 / 人工应回数。误插话率 = 判回复的应沉默数 / 人工应沉默数。中间档单列。每组给出分子、分母，空分母标为无样本。 |
| 续接与回复 | 在有明确对象、话题的样本中计算命中率。人工比较有 QQ 回执的实际回复，离线使用模拟投递捕获的正文，检查是否接对内容、有无重复、多余追问或虚构附件。 |
| 抽取与召回 | 人工标应保存的事实、主体、适用范围、来源及可接受的记忆 ID。分别统计抽取精确率、召回率、检索 Recall@3（对每个有预期记忆的查询，用前三条命中的预期 ID 数除以该查询的预期 ID 总数，再对查询取平均）、串人和越域次数。 |
| 模型成本 | 意图模型和回复模型分开报告每百条入站的实际请求次数、输入输出 token 和费用。列出入站分母与用量覆盖。单价可核验时计算费用，缺价时保留请求数与已观测的 token，费用标缺失。 |
| 决策 P95 | 从入站到最终参与决定落库，按同时具有入站和决策时间的可观测入站去重计数，涵盖回复、沉默以及有决策记录的拦截。每条入站用最后一次决策，给出纳入 P95 的入站数及缺失数。 |
| 确认送达 P95 | 从对应入站到 QQ 平台确认回执，按有完整时间的确认回执计数。同一入站有多笔确认投递时，每笔回执计一次。报告纳入 P95 的确认回执数，并单列失败、未知、未确认和缺时间的投递。另报每百条入站确认的 QQ 投递数。 |

HAP-49 负责冻结评估与配对汇总，HAP-53 负责逐条样本授权、隔离语义执行、预算和脱敏分数写回。使用同一版本的授权样本，分别做三类对照：

- **参与决策。** 固定入站上下文和模型配置，对照参与策略，报告应回召回、误插话及分子分母。话题与回复对象只在有相应标注且两臂均可比较的样本中计分。
- **话题上下文。** 固定参与结果、模型、提示词和生成参数，对照已授权的全群前文与选中话题的前文。盲评是否接对人、接到所补材料、接上正确话题。由对照结果判断调用数、token 和延迟是否改善。
- **角色与记忆增益。** 固定双名称身份、样本、模型、问题和阈值，按同一入站配对比较仅身份、身份加角色、身份加角色与相关记忆三臂。分别报告各臂覆盖和三臂均可比较的分母。固定隔离反例单列越权披露次数。

**验收**　实验应支持逐条配对、按冷场／活跃及纯文字／图文分层复查，并能从获准的线上样本追到决策和实际回执。以调优基线登记质量采纳门槛和成本上限，再查看冻结保留集的候选结果。候选冻结前只查看获准的脱敏汇总。执行前核对逐条授权并按完整双臂或三臂预留预算，计入超时及结果未知的实际请求。样本、标注、配对证据或授权不足时，列明缺口、可用分母和受影响的结论。

## 第二阶段 · 版本化模型实际使用的提示词

- 纳入管理的内容包括回复人设和语气、SystemOne 决策问题、活跃话题选择、记忆抽取、同义检索改写。决策问题同时记录生效的问题顺序、阈值和对应动作，以便分别试验问题措辞与策略。
- 控制台的生效预览、回放和运行共用一处组装逻辑。按层展示账号角色、群聊或私聊补充、服务端说明、运行上下文的来源。将 Langfuse 模板名称和确切版本关联到相应模型调用，复合模板记录各层版本与最终渲染哈希。授权、预算、工具执行和失败停发由服务端强制执行。预览和 trace 沿用正文导出与脱敏设置。
- 在 Langfuse 比较候选，验证后将指定版本同步到 Nagi 本地发布。运行读取本地生效快照，远端暂不可用时仍可对话。回滚后记录重新生效的版本。[版本与发布标签](https://langfuse.com/docs/prompt-management/features/prompt-version-control) · [从模型调用关联 Prompt](https://langfuse.com/docs/prompt-management/features/link-to-traces)

**验收**　选一次测试群真实运行，在控制台定位每段提示词的来源，并用相同输入核对最终渲染哈希。在对应的模型观测上可查 Prompt 版本及该版本的实验分数。发布和回滚各验证一次。

## 第三阶段 · 对比群聊参与策略

- **参与判断。** 先执行作用域授权、频率和预算检查，按接收账号 ID 识别平台结构化 @。自然语言的文字或图文点名交给同一次低成本意图判定中的独立呼叫题。身份取接收账号的配置呼叫名及已核验 QQ 昵称，去重后随问题和请求状态提供，回放使用当次冻结身份。句首、句尾、大小写和简称用于检验语义判断。独立题答 `yes` 时按授权进入回复链路，旧对人分数不能覆盖该答案。答 `no` 时本条保持沉默。答 `uncertain` 时默认沉默，已获准的材料等待另按接续条件核对。引用是上下文证据。引用机器人后明确提问另一位群友时应沉默。
- **同群多话题。** 以机器人账号和群隔离话题。活跃话题提供已授权的候选前文，同群可维护多个并行话题，每条消息可归入其中一个或无归属。语义判定区分参与和话题动作，确认参与后才交给回复 Agent。选取上下文时优先核对明确引用、当前消息与材料、被邀请补发的人及话题最近发言。
- **等待材料。** `wait` 持久化话题、所等材料和有效期限，并释放当前执行。接续须核对同一接收账号、群、原发送人、所等材料、当前授权和时效。明确结束或退出优先处理，结束、到期或撤权后解除或停用等待。无关发言保持沉默且不续期。重启后按原期限和投递记录恢复，已确认的发送须去重，结果未知的发送不自动重试。
- **组装回复。** 先给当前消息、授权引用和选中话题的必要上下文。点名看图时按生成端实际可用的图片作答，缺图或读取失败时简短请对方澄清或补发。更早的聊天按需检索。`history.search` 按当前授权从 PostgreSQL 检索同一会话的留存消息。短词及连续中文支持字面包含，多个词按命中项排序，分数相同时按消息时间与 ID 倒序。工具随会话的历史读取和能力授权提供。 [历史检索实现](../internal/conversation/application/history_search.go)

| 固定回归片段 | 预期 |
| --- | --- |
| 冷场中同一文字呼叫分别以纯文字、同文带可用图、同文带不可用图到达 | 检查实际意图请求中的双称呼、文本、图片输入形态、独立答案与最终动作。可用图片由生成端读取，缺图或不可用时澄清。固定旧对人分数分别验证 `yes` 回复和 `no` 沉默。 |
| 「nagi?」得到回应，随后原发送人按邀请只补一张图，期间夹有无关发言或第三人提交的材料 | 接对人、接到所补材料、仅发送一次。无关发言保持沉默，其他人的材料不消费本人的等待。记录实际意图调用数。 |
| 「我饿了，今天吃什么啊 Nagi」与另一人纠正上个话题里的图片名称交错到达 | 由独立呼叫题确认句尾直呼。饮食和图片分别接入有证据的话题，归属不明的消息可以没有话题。 |
| 引用 Nagi 的消息后明确问另一位群友，或群友互相点名、转述 Nagi、在同名群友之间交流 | 保持沉默。审计能区分引用证据、独立呼叫答案和零投递。 |
| 单独发「你看看这个是什么」，当前、引用和已授权上下文均无媒体 | 先判断是否被呼叫。若决定回复，简短询问指的是什么，避免虚构看过附件或虚构解析失败。 |
| 等待期间重启，或在等待中明确结束后补发材料，或超时后再次点名 | 有效等待按原期限恢复并且仅处理一次。明确结束立即优先，后到材料不恢复旧等待。超时后的点名重新判断，原话题保留结束记录。 |

**首阶段验收**　在隔离合成入口核对入站账号双称呼、实际模型请求、独立答案、最终路由和模拟回执。按应用 PR、镜像构建、GitOps 自动 PR 人工合并及 ArgoCD 同步发布到 dev-nagi。先确认 API 镜像同步并就绪，再发布同一源码提交的 Web 镜像。v2 就绪后，由用户本人在授权群发起一条新的纯文字点名，核对实际模型请求、独立判断和最终回复。对同一条入站，确认 `sent` 投递台账、QQ 平台回执和出站历史记录的三处平台消息 ID 一致后，签收 HAP-51 首阶段和 HAP-48。后续质量对照按第一阶段登记的口径评估。

### HAP-56 · 当前群角色与获准记忆

- 复用 `chat.reply` 的生效发布版本。仅向意图模型提供显式 `intent_context` 中的角色身份、职责及该账号群类型补充层的通用约定。单个群的约定来自本群已批准记忆。旧版本缺字段时按空处理，发布和回滚跟随实际生效层，草稿仅用于预览。双称呼仍取入站身份快照。回复语气、工具指令和示例留在回复配置中。
- 只有当前群开启 `allow_memory_read`、模型披露许可明确允许且来源可核验为同账号同群同会话时，才可披露已批准、有效且可见的相关记忆。披露许可绑定当前 `BotID`、群和实际意图模型目的地（模型及供应商端点），默认拒绝。每次发出请求前都按实际路由复核许可，包括同别名改绑后的路由和回退路由。历史读取使用独立的 `allow_history_read`。来源核验只读元数据，跨账号、跨群、私聊来源和无可验证来源的条目一律排除。先过滤再做有条数、文本量和时间上限的本地检索。超时或无命中时沿用无记忆路径。
- 两种适配器复用同一份背景和既有意图请求。相同路由下新增 HTTP 请求数为零。审计记录角色版本、记忆版本或摘要、采用条数、裁剪和缺失原因，外部遥测脱敏。回放按当前授权和删除状态校验冻结引用，无法还原时标记不可比。验收检查两端实际请求、历史与记忆开关的四种组合、端点改绑、撤权和删除。固定越权反例的正文披露须为零，获准同群样本须有正向命中。按第一阶段的三臂口径评估质量增益。

## 第四阶段 · HAP-52 跨群画像与更正

| 画像与身份键 | 可使用的信息 |
| --- | --- |
| 用户画像 · 机器人账号＋QQ 用户 ID | 本人确认且可跨群使用的称呼、长期偏好。改群名片后仍沿用相同身份。 |
| 群画像 · 机器人账号＋群 ID | 本群约定、共同活动、术语、群友接受的参与频率和表达风格。 |
| 群成员画像 · 机器人账号＋群 ID＋QQ 用户 ID | 此人在本群的名片、参与的话题与本群内成立的互动习惯。 |

HAP-52 是后续独立能力。复用目录身份、记忆候选、审批和替代机制。只有本人明确确认并允许跨群使用的事实才可进入跨群候选。每项事实保留来源消息、主体、获准转用范围、确认时间和更正状态。更正和撤回按实际确认的范围生效。先核对当前群是否在获准范围内，再做相关性排序。A 群的一次约饭仅用于 A 群，私聊内容沿用原会话授权。称呼更正经确认后替换原事实，旧事实退出生效结果。

**验收**　用同人不同群、同名不同人、转述、群体事实、更正称呼和同义问法做配对测试。以同一主体、同一条已确认事实做成对用例，验证在获准群可以召回，在未获准群无法召回。更正后的事实正常召回，原事实退出生效结果。固定反例的验收门槛为串人、越域和私聊事实泄露各 0 次。盲评实际回复是否在合适的话题才使用记忆，并记录画像命中对自然度与 token 的影响。
