# 提交前清理

## 触发时机

每次 commit、push、开 PR 前，以及一次任务收尾时（与 `change-scope.md` 的最终范围检查一并执行）。

## 必查项

- `git status --short`、`git diff --stat`、未跟踪文件的实际内容。
- 逐项对照当前需求：这份改动服务于哪条需求，去掉它是否仍然成立。

## 必须清理

- 一次性脚本、临时 SQL、调试代码与调试日志、临时数据文件。
- 构建与测试产物：`bin/`、覆盖率文件、profile、测试生成的快照。
- 注释掉的旧实现、失败方案残留、为绕过问题加的无用兼容分支。
- 重复或过期文档、与当前代码不一致的命令示例。

## 文档标准

- 只写"做什么、怎么用、怎么验证"，不写背景叙事与实现流水账。
- 不复述代码或配置；同一事实只维护一处，其余位置引用。
- 没有明确读者的文档不新增；文档过期就改写或删除，不叠加"补充说明"。
- 命令示例必须可直接执行，并与仓库当前结构和脚本保持一致。

## 边界

- 不删除他人内容、历史文档或业务代码，除非用户明确授权。
- 清理只针对本次任务产生或已确认无用的文件；不确定时报告，不擅自删除。
- 不以"看起来没用"为由删除迁移文件、测试或配置项。
