# coding

以用户当前需求为边界，完成必要实现和验证，保留可审查的最小差异。
本技能提供行为约束，不提供文件权限隔离或合并门禁。

## 加载约束

涉及 OneBot 协议、上下文分层、事件分发或新增业务上下文时，同时加载
[OneBot 技能](../onebot/SKILL.md) 的适用参考；纯技术工具调整不必加载。

在操作前判断任务属于审查、开发还是撤销，并读取适用文件：

- 所有相关任务必读 [防乱改约束](references/change-scope.md)。
- 实施代码修改、设计或架构审查时，读取 [编码架构约束](references/architecture.md)。
- 分析测试、新增或修改或删除测试、选择代码修改的验证方式时，读取
  [测试约束](references/testing.md)。撤销后的必要验证也遵循该文件。
- 新增、调整或审查代码注释（包括函数文档注释）时，读取
  [注释约束](references/comments.md)。
- 涉及数据库 schema、迁移、SQL 或数据写入方式时，读取
  [数据库与迁移约束](references/database.md)。
- 执行 commit、push 或准备 PR 前，读取 [提交前清理](references/hygiene.md)。

同一任务只需读取一次未发生变化的约束；任务内容变化时补读适用部分。
不要将全部约束重复写入计划、注释或项目文档。

## 使用原则

- 用户的明确要求优先于技能中的默认选择；遵守更高优先级指令和实际执行权限。
- 最佳实践约束本次实现的质量，不自动产生重构、测试、文档或额外功能需求。
- 已批准的任务和方案构成授权，不因技能要求分析或检查而反复请求确认。
- 纯审查保持只读；必要修改已有授权时直接完成，不停留在建议或计划。
- 约束文件不可读取时，报告缺失项，不声称已加载，也不自行创建替代规则。

## 完成条件

用户明确要求已满足，`just verify`（或等效的四条 Go 命令）通过，没有已知由本次
修改引入的错误，最终差异仅含必要改动时，立即停止。无法执行的验证应明确报告，
不把跳过或未验证描述为通过。

## 扩展方式

仅在用户要求新增或调整约束时维护本技能。新主题放入独立参考文件，在本入口说明
何时读取，并保持每条规则只有一个主要维护位置。不要创建预留文件或重复规则全文。
