# OneBot 上下文开发约束

先加载 coding 的适用约束，再使用本技能。用户需求决定范围；本技能不扩大任务、
操作权限，也不覆盖更高优先级指令。

## 按任务加载

- 所有相关任务先读 [架构总览](../../../docs/architecture.md) 和
  [审查清单](references/review.md)。核对当前代码，文档不能代替事实。
- 划分上下文、改变依赖方向或调整端口契约：读 [分层与边界](references/layers.md)。
- 新增业务上下文、处理器或配置域：读 [扩展指南](references/extension.md)。
- 修改 WS 传输、帧编解码、echo 匹配、事件分发或生命周期：读
  [协议与运行时](references/protocol.md)。

## 必经流程

1. 核对当前代码、调用方、工作区差异和需求；区分协议事实、明确要求与假设。
2. 用业务语言描述用例，确定所属上下文与端口所有者。
3. 列出不变量、接口、数据流、失败路径和并发保护。小改动简述即可，不能跳过判断。
4. 对照架构文档检查方案。缺失协议事实先查 SnowLuma 文档或向用户澄清，不以技术
   偏好补造行为。
5. 在授权范围内实现，运行 `just verify` 与必要的 `go test -race`，审查最终差异
   与文档一致性。

遇到与架构文档冲突的建议时，指出具体冲突、证据和后果，给出满足原需求的替代
方案；实现选择可在原范围内纠正，不反复请求批准。不能私自修改检查或文档以掩盖
违规；用户明确改变既定要求时说明取舍并同步设计。
